# 去处 Somewhere

> 把一种感觉，翻译成一个地方。

一个从“感觉”出发的反向旅游 Agent C 端原型。用户不必先知道目的地，只要描述想进入的天气、节奏与生活，产品会先结构化理解，再展示 Agent 探索、比较和现实取舍，最后给出三个有角色差异的目的地与三日低压力提案。

## 本地运行

环境要求：Node.js `>=20.19.0`，pnpm `>=10`。项目已声明 pnpm 版本，优先使用 pnpm 保证依赖解析一致。

```bash
pnpm install
pnpm dev
```

如果只使用 npm：

```bash
npm install
npm run dev
```

默认支持两种模式：当前本地 `.env.local` 可开启 TokenHub 在线氛围解析；如果 TokenHub 不可用，页面会自动回退到内置 Demo 数据，不会阻塞演示。开发代理会**优先读取** `TOKENHUB_API_KEY` 环境变量；仅在该变量未配置时，才回退读取本地 `key.md` 的 `tokenhub:` 值。

安全说明：开发服务只绑定 `127.0.0.1`，并阻止对 `key.md`、`.env*`、`.git` 的 HTTP 访问。请将 TokenHub key 视为开发密钥，不要分享或提交；若曾在局域网运行旧版本，建议立即在 TokenHub 控制台轮换该 key。

## 构建与静态预览

```bash
pnpm build
pnpm preview
```

也可以使用 `npm run build` 和 `npm run start`。`start`/`preview` 会通过 Vite 静态服务器提供 `dist`，适合验证生产产物；不要直接把项目根目录的源码 `index.html` 当成最终页面打开。构建后资源使用相对路径，因此 `dist` 可以部署到域名根路径、子路径，也可以交给常规静态托管服务。

如果浏览器对 `file://` 下的 ES Module 有安全限制，直接双击 `dist/index.html` 仍可能被拦截，此时请使用上面的 `pnpm preview`，或使用任意静态文件服务器打开 `dist`。

## 核心体验

- 旅行委托卡：支持自然语言、4 组灵感示例、字数提示、空输入提示和 Ctrl/Cmd + Enter 提交。
- 氛围翻译：展示情绪强度、环境标签、节奏、人群与现实约束，标签可删除。
- 世界探索：用抽象地图表达探索范围和 5 个可理解的任务状态，不展示模型私有推理过程。
- 三个目的地：最佳匹配、意外选择、更容易抵达；每个结果都有匹配理由与现实取舍。
- 氛围微调：重新安静、变暖、少商业化、更易抵达、预算降低、只看国内。
- 现实选项：在出发前选择国内外范围、天数与预算，约束会一并传给 TokenHub。
- 详情提案：为什么是这里、三日低压力路线、现实提醒、相似但不同的去处。
- 时间可行性：每一天按 POI 停留、已列移动时长和明确的换点弹性计算 8 小时参考预算；会标出留白、偏紧或过满，不把它伪装成实时排程。
- 交互地图：MapLibre GL JS 驱动的页面内地图；结果首屏只显示轻量入口，用户点击“加载交互地图”后才下载地图模块。点击候选卡或地图坐标即可聚焦目的地并绘制多日编辑路线。用户主动点击“核验当前日路线”后，前端通过受控 `/api/route` 逐段获取道路路线、距离与预计时长并显示进度；失败会保留编辑路线并说明原因。地图底图异常时提供重试与可见地点列表降级。
- 抵达段：跨城抵达与每日市内路线分开展示。当前只有用户选择上海、北京、广州或成都并选择自驾时，才能按需核验真实道路距离与预计时长；高铁、飞机、公共交通会明确标注为“班次服务未接入”，不生成伪路线。
- 按需证据覆盖度：将天气、每日道路路线与自驾抵达段的用户主动查询汇总为 0–100% 覆盖度；它不是“可出发”评分，静态 POI 的营业、预约、票务与安全仍须逐项确认。
- POI 地图参照：行程中每个 POI 可由用户按需向受控 BFF 查询 OpenStreetMap Nominatim 的**附近地图参照**，返回来源链接、距离与查询时间；它不证明同一 POI，也不核验营业、预约或安全状态。
- 附近地点发现：详情页可由用户选择公园、咖啡、博物馆或观景点，按需发现 OpenStreetMap 附近地图条目并按距查询中心的直线距离排序、跳转来源。结果仅是临时探索候选，不会自动加入行程，也不等于审核过的内容、营业或预约事实。
- 出发前天气核验：用户选择日期后，受控 `/api/weather` 只返回该地点该日的温度、降水概率与风速，并展示来源；它不替代气象预警、实时交通或安全判断。
- 收藏和分享摘要：使用 localStorage 保存收藏；收藏会形成可清除的本地偏好记忆，在硬条件筛选后以可解释加分重排候选；分享按钮复制简短提案。
- 最近委托恢复：文字与结构化范围/天数/预算/出发地/交通条件只保存在当前设备；刷新后恢复编辑状态，但不会自动重新调用 AI，也不会保存媒体。
- 出发决策包：将每日 POI、地图入口、当前道路路线状态与待确认事项导出为 Markdown 或复制到剪贴板；用户主动查询后，才会写入仍在 15 分钟有效窗口内的天气、每日道路路线，或自驾抵达段的来源、时间、距离、时长与路段数；过期证据会要求重查。它不包含原始委托、上传媒体、坐标/路网几何、预订或价格信息，也不把静态编辑数据写成已核验事实。
- 多模态灵感：支持本地图片预览、粘贴公开 HTTPS 图片链接和浏览器语音转写。图片文件需要明确授权、图片链接需要再次点击“理解”才会送往受控视觉接口；接口只回传受限标签。语音由浏览器先转成可编辑文字，只有用户确认的文字进入目的地 Agent；音频文件仍只作本地播放，不会上传。

## AI / TokenHub 接入

开发模式已经接入真实 TokenHub：Vite 服务端代理优先读取 `TOKENHUB_API_KEY`，未配置时才读取本地 `key.md` 中的 `tokenhub:`；随后调用 TokenHub 的 OpenAI 兼容 `/v1/chat/completions` 接口。浏览器先接收结构化 `VibeProfile`，用户确认后再由独立的 `/api/destination-recall` 动态召回 3 个不同角色的目的地。服务端会校验范围、天数、角色、坐标与体验纲要结构，拒绝不完整模型输出；返回的地点、坐标和体验锚点都明确标为**未核验的 Agent 草案**。在线服务不可用时，页面会立即退回本地编辑库，保证演示不中断。已接入用户主动触发的 OSM 附近地点发现，但真实 POI 召回与审核数据层尚未接入。

TokenHub 官方入口使用广州区域 `https://tokenhub.tencentmaas.com`，模型由 `TOKENHUB_MODEL` 配置。项目当前 `.env.local` 使用 `hy3`；如果账号没有该模型，可先用 `GET /v1/models` 查询后替换。

页面右上角的「设置」支持本机覆盖旅行 Agent 模型、图片理解模型与 TokenHub Key；模型设置会持久保存在该设备，Key 仅保留在当前浏览器会话，并通过同源 BFF 发送给官方 TokenHub 网关。它会覆盖下一次偏好解析、目的地召回和图片理解请求；关闭浏览器会话后 Key 自动失效。为避免将 BFF 变成任意地址代理，浏览器侧仅允许官方 TokenHub 广州网关；生产环境仍建议将平台 Key 配置在服务端密钥管理中。

可选的图片理解使用独立的服务端接口，模型由 `TOKENHUB_MEDIA_MODEL` 配置；图片可以是明确授权的本地 JPG/PNG/WebP，或用户主动粘贴的公开 HTTPS 链接。服务端不会下载链接，只会拒绝内网/本地/带凭据 URL 后将其转交视觉模型，并把上游结果收敛为受限标签。腾讯云公开的 TokenHub 多模态协议支持 `image_url`；默认示例模型为 YT‑VITA，具体账号可用性仍须验证，以其[官方多模态理解文档](https://cloud.tencent.com/document/product/1823/130988)为准。当前账号的真实视觉请求仍出现超时或不可用，**尚未证明视觉模型可稳定使用**。声音输入采用浏览器语音转写，不会上传原始音频文件。

地图无需额外 Key：页面内已接入 MapLibre GL JS 和 OpenStreetMap 栅格底图，结果卡同时保留 OpenStreetMap 外链。目的地服务请求、地图中心与 POI 使用同一套 WGS84 坐标；朱红虚线是产品给出的编辑行程示意。用户主动核验时，通过 `/api/route` BFF 叠加道路路线并展示距离、预计时长、来源与规划时间。BFF 有输入限制、12 秒超时、成功缓存与公共 OSRM 的 1 req/s 限速；生产通过 `OSRM_URL` 切换自托管或签约供应商。若仍使用公共 OSRM/Nominatim，可设置 `UPSTASH_REDIS_REST_URL` 与 `UPSTASH_REDIS_REST_TOKEN` 启用跨实例原子限流；保护层配置后不可用会安全失败，不会绕过限制请求公共上游。POI 可按需取得 Nominatim 的附近地图参照，也可在预设类别内发现附近地图条目并按直线距离排序；两者均受用户点击、每秒最多一个公开请求与成功缓存约束，且需配置 `NOMINATIM_USER_AGENT`。发现结果不是审核库，不能用于断言营业、预约、安全或公共交通规划。Nominatim 的公开服务仅适合低量演示，必须遵守其[使用政策](https://operations.osmfoundation.org/policies/nominatim/)，生产应可切换至自托管或签约服务。

天气核验通过 `/api/weather` BFF 按用户选择的地点和日期向 Open-Meteo 查询日级 `weather_code`、最高/最低温、最高降水概率与最大风速；服务端有 2KB 输入上限、12 秒超时和 10 分钟成功缓存，浏览器不会接触上游原始响应。天气预报会变化且不等于预警，因此页面保留查询时间与安全提示。字段语义以 [Open-Meteo 官方文档](https://open-meteo.com/en/docs) 为准。

密钥永远不要放进 `VITE_` 变量、浏览器 bundle 或提交到 Git。开发时优先使用未提交的 `TOKENHUB_API_KEY`；`key.md` 仅是兼容性的本地测试回退。详见 [生产 API 接入说明](docs/PRODUCTION_API.md)。

## Agent 工作流

```text
用户委托 → Vibe Interpreter → Place Explorer → Reality Checker → Journey Editor
               结构化氛围       候选召回          现实约束核验       可阅读提案
```

实时天气、价格、交通、开放时间和签证信息均需在真实接入时标注来源与更新时间；原型中的现实信息是示例数据，不替代官方核验。

## 技术与限制

- Vite + React + TypeScript + 原生 CSS + lucide-react。
- 地图使用 OpenStreetMap 在线底图；探索阶段仍保留轻量 CSS 地理档案视觉。
- 图像使用远程 Unsplash 氛围图；加载失败时卡片布局仍然成立。
- 后续：部署 TokenHub BFF、引入可维护的真实 POI/来源/更新时间数据层、接入生产级路线与出发前核验；高铁/火车目前仅提供 12306 官方查询出口，不读取或核验班次、票务与换乘。图片理解接口还需在目标账号验证稳定性并完成生产部署；如需转写用户上传的音频文件，应另接入 ASR 服务。
