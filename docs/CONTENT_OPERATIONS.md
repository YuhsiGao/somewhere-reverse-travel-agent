# 去处 Somewhere｜POI 内容运营契约

本项目当前随前端发布的地点与行程均为 `static-editorial-demo`。它们只能用于演示“意图 → 候选 → 决策包”的工作流，不能被表述为实时营业、可预约、可预订或安全可达的事实。

## 1. 生产 POI 的最小记录

每条可进入用户推荐的 POI 必须具备以下字段：

| 字段 | 要求 | 目的 |
| --- | --- | --- |
| `id` | 稳定、不可复用的内部 ID | 防止地点改名后收藏和行程错配 |
| 名称、坐标、类别 | 编辑确认并通过坐标范围校验 | 支持地图、路线与筛选 |
| `source.url`、`source.label` | 可公开访问的来源 | 让用户和审核者追溯事实 |
| `source.updatedAt` | ISO 日期 | 计算内容新鲜度，不冒充实时 |
| 适用季节、建议停留 | 有编辑依据 | 支持低压力行程与时间预算 |
| `operatingRisk` | 明确的待核验事项 | 防止把预约、封路或营业风险藏起来 |
| 审核状态 | `draft` / `reviewed` / `retired` | 未审核内容不可进入候选召回 |

## 2. 发布门槛

1. 编辑录入后必须补齐来源与更新时间；缺失时只能处于 `draft`。
2. 审核者检查名称、坐标、来源链接、适用季节和风险说明，才可标记 `reviewed`。
3. 每 90 天复核一次；超过阈值只保留为“可能过期的编辑内容”，不添加强事实文案。
4. 来源失效、地点永久关闭或坐标不确定时标记 `retired`，从召回和决策包移除。
5. 营业、票务、道路、天气、签证与价格永远走按需数据源或官方渠道，不写回为长期“真相”。

## 3. 自动化校验与人工核验的边界

- 当前 `catalog-health` 会检查 POI 来源、更新时间、新鲜度和风险提示，并在 UI 中显示“静态编辑示例，非实时数据”；`catalog-validation` 则作为随仓库运行的内容发布门槛，拒绝重复 ID、越界坐标、缺失公开来源、无效日期和缺失风险提示。当前数据仍是 `static-editorial-demo`，该校验不等同人工审核或线上事实验证。
- `/api/poi-verification` 只提供 OpenStreetMap 附近地理参照，不能升级为 POI 身份或营业验证。
- `/api/route` 与 `/api/weather` 都是一次性按需核验；决策包会保留路线状态，但要求临近出发重新查询。
- 上线前应在 CI 中拒绝缺失来源、无效日期、重复稳定 ID、越界坐标和 `draft` 状态的候选数据。

## 4. 首期供给策略与业务指标

先做 20–50 个国内短途城市/周边场景，而非覆盖所有目的地。每城先维护 10–20 个审核 POI 和 2–4 条低压力主题路线；通过“无结果率、候选打开率、决策包导出率、路线核验率、采纳/放弃原因”决定扩充哪类场景。它验证的是旅行决策价值，不等价于预订 GMV。
